# 0007. 题目分型，客观题由服务端判分

- 状态：Accepted
- 日期：2026-11-07
- 决策者：全员

## 背景

v0.1 把所有错题当成同一种东西，复习时一律"看答案 → 自评记住/模糊/忘记"。问题很明显：

- 选择题明明有标准答案，却让用户自己判对错，等于允许自我欺骗
- 自评数据不可信，"正确率"这个指标就没有意义
- 组卷自测无法自动出分，只能叫"练习"

## 决策

1. **题目带类型**：`SINGLE` 单选 / `MULTIPLE` 多选 / `JUDGE` 判断 / `BLANK` 填空 / `SUBJECTIVE` 主观 / `IMAGE` 图片题。
2. **客观题（前四种）在服务端判分**，前端只提交作答，不提交"我答对了"。
3. **主观/图片题保留自评**，评 0/1/2 直接作为 SM-2 的 rating。
4. **判分结果映射为 rating**：`1.0 → 2`（记住）、`(0,1) → 1`（模糊）、`0 → 0`（忘记）。这样"自动判分"和"手动自评"共用同一套排期逻辑，复习服务不需要分叉。
5. **选项与答案存 JSON 字段**（`options` / `answer`），用自定义 `TypeHandler` 映射为 `List<Option>`；不建 `question_option` 表。

## 后果

**正面**

- 客观题的复习数据真实可信，统计才有意义
- 组卷可以自动出分，自测体验成立
- 一套 rating 映射，SM-2 只有一条代码路径
- 选项 JSON 避免了 6 种题型共用一张表的稀疏问题，也不用多建 2~3 张表

**负面**

- **录入成本上升**：出一道选择题要填选项和答案，比"拍张照"麻烦得多
  - 对冲：提供"从视频段落/资料文本快速出题"的入口
- 选项存 JSON 后，无法用 SQL 直接按"选了 B 的人有多少"做聚合
  - 课设范围内不需要这类分析，真需要时再从作答明细里解析
- 判分逻辑有 6 个分支，测试用例要覆盖全（尤其是多选漏选/错选）

## 备选方案

| 方案 | 为什么不选 |
|---|---|
| 全部自评 | 数据不可信，组卷无法出分，功能退化成"翻卡片" |
| 只做选择题，放弃图片题 | 大量错题来自纸质卷子/PPT 截图，砍掉会丢掉真实场景 |
| 用大模型判主观题 | 结果不稳定、有调用成本，答辩无法保证复现 |
| 选项建独立表 `question_option` | 更"范式"，但多两张表、多一次 join，收益只在复杂查询场景 |
